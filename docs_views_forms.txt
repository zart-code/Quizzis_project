--- _handle_form(request, form_class, template_name, success_url, ...) ---

Что делает: Универсальный обработчик форм. Убирает дублирование логики POST/GET
для регистрации и логина.

Связи:
  - POST: Создаёт форму из request.POST → валидирует
    → CustomUserCreationForm: создаёт User в БД + login(request, user)
    → StyledAuthenticationForm: достаёт User из БД + login(request, user)
    → редирект на success_url
  - GET: Создаёт пустую форму → передаёт в шаблон template_name
  - Вызывается из: register_page()


--- main_page(request) ---

Что делает: Рендерит главную страницу с формой ввода кода лобби.

URL: / (name="main_page")
Шаблон: main_page.html
Контекст:
  - join_pin_prefill — из GET ?pin=... (предзаполнение поля кода)
  - highlight_nickname — True если ?highlight=1 и пользователь не авторизован
Кто перенаправляет сюда:
  - join_lobby_view (гость зашёл по прямой ссылке без ника)
  - logout_view
  - join_by_code (при ошибке)


--- register_page(request) ---

Что делает: Страница регистрации нового пользователя.

URL: /register/ (name="register_page")
Шаблон: register.html
Форма: CustomUserCreationForm (из main/forms.py)
БД:
  - Создаёт User (django.contrib.auth.models.User)
  - Автоматически создаётся Profile через сигнал post_save в models.py
После успеха: login(request, user) → редирект на main_page


--- login_page(request) ---

Что делает: Страница входа в систему.

URL: /login/ (name="login_page")
Шаблон: login_page.html
Форма: StyledAuthenticationForm (из main/forms.py)
БД: form.get_user() — ищет User по credentials
GET-параметр next: Если пришёл с защищённой страницы (@login_required),
  после логина вернёт туда
После успеха: login(request, user) → редирект на next или main_page


--- logout_view(request) ---

Что делает: Выход из системы.

URL: /logout/ (name="logout")
Действие: logout(request) — очищает сессию, удаляет auth cookie
Редирект: → main_page


--- quizzes_view(request) ---

Что делает: Страница "Все квизы" — каталог опубликованных квизов.

URL: /quizzes/ (name="quizzes_view")
Шаблон: quizzes_view.html
БД запрос:
  - Quiz.objects.filter(status=Quiz.ACTIVE) — только опубликованные
  - .select_related("creator", "current_revision") — JOIN с автором и ревизией
  - .annotate(...) — для каждого квиза считает:
    • passed_count — кол-во завершённых прохождений текущей ревизии
    • avg_score_percent — средний процент
    • avg_score_points / avg_max_points — средние баллы
  - Фильтр current_revision_filter — статистика только по текущей ревизии
Сортировка (GET ?sort=):
  - "new" (по умолчанию) — по дате создания
  - "popular" — по количеству прохождений
  - "best" — по среднему проценту
Поиск (GET ?search=): title__icontains — подстрока в названии
Контекст → шаблон: quizzes (QuerySet), current_sort, search_query


--- join_by_code(request) ---

Что делает: Обрабатывает POST-форму "Войти по коду" с главной страницы.

URL: /join/ (name="join_by_code")
Метод: Только POST
Входные данные: pin (код лобби), nickname (ник гостя)
БД запрос: GameSession.objects.filter(pin=pin).first()
Логика:
  1. Сессия не найдена → messages.error → редирект main_page
  2. Сессия FINISHED → messages.error("Эта игра уже завершена") → main_page
     (гость НЕ создаётся)
  3. Пользователь не авторизован:
     - _get_request_user(request, guest_name=nickname) — создаёт/обновляет
       гостевого User в БД (username = "guest_<ник>")
     - Сохраняет guest_user_id в Django-сессии
     - Устанавливает флаг guest_nickname_set
  4. Редирект → join_lobby/<pin>/?from_code=1
Связь с _get_request_user: Создаёт User в БД
Связь с join_lobby_view: Перенаправляет туда с ?from_code=1

--- _get_guest_username(guest_name, exclude_user_id=None) ---

Что делает: Формирует уникальное имя гостя.

Логика:
  - Если guest_name задан: очищает от спецсимволов → "guest_<очищенный_ник>"
  - Если не задан: "guest_<uuid4_hex[:8]>"
  - Проверяет уникальность в БД (User.objects.filter(username=...))
  - Если конфликт — добавляет суффикс _1, _2, ...
  - exclude_user_id — исключает текущего гостя из проверки (при переименовании)
БД: User.objects.filter(username=...) — проверка уникальности


--- _get_request_user(request, guest_name=None) ---

Что делает: Возвращает пользователя для игры — реального или гостевого.

Логика:
  1. Если request.user.is_authenticated → возвращает его
  2. Если в сессии есть guest_user_id:
     - Ищет User в БД по ID
     - Если не найден (удалён) — очищает сессию
     - Если найден и передан guest_name — обновляет username
  3. Если гостя нет — создаёт нового User через create_user()
     - Сохраняет guest_user_id в Django-сессии
БД:
  - User.objects.get(pk=guest_user_id) — поиск существующего гостя
  - User.objects.create_user(username=...) — создание нового
Вызывается из: join_by_code, join_lobby_view, session_play_view

--- join_lobby_view(request, pin) ---

Что делает: Присоединение игрока к лобби.

URL: /lobby/<pin>/join/ (name="join_lobby")
Шаблон: join_lobby.html (или lobby_error.html при ошибке)
Логика (по порядку):
  1. Если сессия FINISHED → ошибка "Игра уже завершена" (гость НЕ создаётся)
  2. Если не авторизован:
     - Проверяет from_code и guest_nickname_set
     - Если зашёл по прямой ссылке без ника → редирект на main_page с ?pin=&highlight=1
  3. _get_request_user(request) — получает/создаёт пользователя
  4. Проверки: просрочка, хост ли это, уже в игре, статус, блокировка, лимит 25
  5. GameParticipant.objects.get_or_create(...) — создаёт участника
  6. Если created: заполняет display_name через resolve_display_name_from_user
  7. Сохраняет participant.id в request.session["lobby_participant_<pin>"]
БД:
  - GameSession (get_object_or_404)
  - GameParticipant (get_or_create, count)
  - User (через _get_request_user)

--- session_play_view(request, pin) ---

Что делает: Основная view игрового процесса — показ вопросов, приём ответов.

URL: /session/<pin>/play/ (name="session_play")
Шаблон: session_play.html (игра) или session_results.html (результаты)
Логика:
  1. Поиск участника:
     - Сначала по lobby_participant_<pin> из HTTP-сессии (для удалённых гостей)
     - Затем по user через _get_request_user
  2. Если сессия FINISHED → обновляет QuizResult → рендерит session_results.html
  3. Если IN_PROGRESS:
     - GET: Показывает текущий вопрос с таймером
     - POST (ответ):
       a. Проверяет, не отвечал ли уже (GameAnswer exists)
       b. score_question() — подсчёт баллов
       c. Обновляет participant.score, participant.is_answered
       d. Создаёт GameAnswer
       e. Если все ответили → переход к следующему вопросу
       f. Если вопросы кончились → session.status = FINISHED → cleanup_guest_users()
БД:
  - GameParticipant (поиск, обновление score)
  - GameAnswer (проверка дубля, создание)
  - QuizResult (создание при первом входе, обновление при завершении)
  - GameSession (обновление current_question, status)
  - User (удаление гостей через cleanup_guest_users)
Связь с cleanup_guest_users: Удаляет гостей после завершения сессии
Связь с score_question: Подсчёт баллов за ответ
Кэширование: Отключено (Cache-Control: no-store)

--- create_quiz_view(request) ---

Что делает: Создание нового квиза.

URL: /quiz/create/ (name="create_quiz")
Доступ: @login_required, роль TEACHER или ADMIN, не забанен
Логика POST:
  1. Извлекает title из POST
  2. collect_question_payloads_from_post(request) — парсит вопросы из POST
  3. Валидация: title не пустой, есть хотя бы 1 вопрос

  5. create_revision_from_payloads(...) — создаёт QuizRevision + RevisionQuestion + RevisionAnswer
БД:
  - Quiz.objects.create(...)
  - QuizRevision, RevisionQuestion, RevisionAnswer (через create_revision_from_payloads)

--- play_quiz_view(request, quiz_id) ---

Что делает: Одиночное прохождение квиза (из раздела "Все квизы").

URL: /quiz/<quiz_id>/play/ (name="play_quiz")
Шаблон: play_quiz.html
Доступ: Все (авторизованные и анонимные)
Логика:
  - current_user = request.user если авторизован, иначе None
  - Черновик доступен только создателю
  - GET (первый вход):
    • Если авторизован: создаёт QuizResult в БД (score=0, completed=False)
    • Инициализирует сессионные ключи: quiz_<id>_log, _index, _answered
  - POST action="answer":
    • Проверяет, не отвечал ли уже (answered_questions в сессии)
    • score_question(question, request, timed_out) — подсчёт баллов
    • Сохраняет результат в сессию (quiz_<id>_log, quiz_<id>_answered)
    • Рендерит результат ответа (правильно/неправильно, баллы)
  - POST action="next":
    • Показывает следующий вопрос
  - POST action="finish":
    • Суммирует баллы из quiz_<id>_log
    • Если авторизован: обновляет QuizResult (score, completed=True)
    • Очищает сессионные ключи
    • Удаляет гостя из БД (если есть guest_user_id и нет активных лобби)
    • Рендерит финальный экран с результатом
БД:
  - Quiz (get_object_or_404)
  - QuizResult (create при старте, update при финише) — только для авторизованных
  - User (удаление гостя при финише)
  - GameParticipant (проверка активных сессий гостя)
Связь с score_question: Подсчёт баллов
Связь с get_quiz_questions: Получение вопросов текущей ревизии
Хранение состояния: Django session (quiz_<id>_log, _index, _answered, _result_id)

--- profile_view(request, user_id=None) ---

Что делает: Страница профиля пользователя.

URL: /profile/ (name="profile") или /admin/user/<user_id>/ (name="admin_user_profile")

  - QuizResult...order_by("-completed_at")[:5] — последние 5 прохождений
  - UserAchievement.objects.filter(user=user) — достижения пользователя
  - Achievement.objects.all() — все достижения (для отображения locked/unlocked)
Контекст: profile_user, total_quizzes, completed_quizzes, average_score,
  category_stats, recent_quiz_history, achievements, is_admin_view, is_student

--- edit_profile_view(request, user_id=None) ---

Что делает: Редактирование профиля (своего или чужого для админа).

URL: /profile/edit/ (name="edit_profile") или /admin/user/<user_id>/edit/
Доступ: @login_required; чужой — только админ
Шаблон: edit_profile.html
Логика POST:
  1. Обновление username (с проверкой уникальности в БД)
  2. Обновление email (с проверкой уникальности)
  3. Обновление пароля (с проверкой совпадения и длины ≥8)
  4. user.save()
  5. update_session_auth_hash(request, user) — чтобы не разлогинило после смены пароля
БД:
  - User.objects.filter(username=...).exclude(pk=...).exists() — проверка уникальности
  - user.set_password(password) + user.save()
Редирект: → profile или admin_user_profile
